Le déclencheur documenté : @nextnode-solutions/standards présent dans package.json, ou toute configuration de tooling dans un projet NextNode. Le package standards est config-only — aucun code runtime, aucun build ; les projets étendent ses exports.

  • Sans argument — audit complet de conformité du projet.
  • oxlint · typescript · tsdown · vitest · configs — détail d'un outil, chacun adossé à un sous-fichier du skill.

02Checklist d'un projet conforme

Dix fichiers de config à la racine, plus des champs package.json obligatoires.

  • racine du projet/
    • oxlint.config.ts — extends standards/oxlint (oxlint ≥ 1.58.0)
    • oxfmt.config.ts — extends standards/oxfmt (oxfmt ≥ 0.43.0)
    • tsconfig.json — extends standards/typescript/{library|nextjs|astro}
    • tsdown.config.ts — packages publiables uniquement
    • vitest.config.ts — standards/vitest/{backend|frontend|astro}
    • commitlint.config.js — standards/commitlint
    • lint-staged.config.js — standards/lint-staged (husky v9+)
    • .releaserc.json — semantic-release-monorepo + standards (publiables)
    • .editorconfig — copié depuis standards
    • .npmrc — copié depuis standards
Piège CI packageManager est obligatoire : pnpm/action-setup y lit la version de pnpm. Version exacte alignée sur la racine du monorepo — jamais de range ni de major seul, sinon le pipeline casse.

oxlint — règles relâchées et overrides

Catégories : correctness → error, suspicious et perf → warn. Le plugin custom no-type-assertion bannit les casts as (sauf as const), embarqué dans le package — pas d'install séparée.

Fichiers config/test (*.config.*, *.test.*, *.spec.*) : no-console off, no-explicit-any warn, no-magic-numbers off. Les overrides projet s'ajoutent par-dessus la base via extends: [standardsConfig] — jamais en affaiblissant les règles cœur.

oxfmt — style imposé

Tabs (largeur 4), LF, print width 80, pas de point-virgule, single quotes (double en JSX), trailing commas partout sauf JSON, tri d'imports automatique (builtins → external → internal → parent → sibling → index). package.json est ignoré par oxfmt : better-sort-package-json le possède via lint-staged — ne pas toucher, les deux outils se contredisent et flip-floppent.

semantic-release — ordre d'extends critique

semantic-release-monorepo doit être dans l'array extends du .releaserc.json, monorepo en premier, standards en second. Le flag CLI -e écrase silencieusement la liste de plugins et perd @semantic-release/git. Le package standards embarque les plugins en dépendances transitives — le consommateur n'installe que semantic-release.

commitlint — format des commits

Format type(scope): subject. Types : feat fix docs style refactor perf test build ci chore revert. Type et scope en lowercase, sujet sans majuscule initiale ni point final, header ≤ 100 caractères.

04Règles du skill

⚠️ Interdit

  • Affaiblir les règles cœur oxlint (no-explicit-any, eqeqeq, strict…)
  • Espaces d'indentation, points-virgules, double quotes hors JSX
  • Trier les imports à la main
  • Imports de type inline : import { type Foo }
  • Sauter astro check sur un projet Astro
  • Compter sur le tsconfig étendu pour hériter exclude
  • packageManager en range ou absent

✅ Obligatoire

  • Overrides projet uniquement par-dessus la config de base
  • Tabs partout (oxfmt l'impose), pas de point-virgule, single quotes
  • Laisser oxfmt ordonner les imports
  • Imports de type séparés : import type { Foo }
  • pnpm run lint ET pnpm astro check sur Astro
  • "exclude": ["vitest.config.ts"] dans chaque tsconfig projet
  • pnpm pinné à la version exacte du monorepo
