# Pipeline Architecture

## Workflows

Three reusable workflows — callers choose one directly (no routing):

### `publish-package.yml` (type=package)

```
plan → quality (matrix) → publish (semantic-release)
```

- Publish only runs on `main` branch and when `plan.outputs.publish == 'true'`
- Uses `semantic-release` via `pnpm exec` (plugins come from `@nextnode-solutions/standards` deps)
- After publish: runs `publish-result` command to parse output and write summary
- Requires `NEXTNODE_APP_ID`, `NEXTNODE_APP_PRIVATE_KEY`, `NPM_TOKEN` secrets

### `deploy-dev.yml` (type=app, development)

```
plan → quality (matrix) → deploy (stub)
```

### `deploy-prod.yml` (type=app, production)

Two modes based on `environment.development`:

```
# When development=true (default):
plan → prod-gate → deploy

# When development=false (direct-to-prod):
plan → quality (matrix) → deploy
```

Prod-gate calls GitHub API to verify dev pipeline check runs passed for the commit.

## Quality matrix

Generated by `buildQualityMatrix(scripts, project)`:

| Condition | Command format |
|-----------|---------------|
| `filter` is false | `pnpm {script}` |
| `filter` is set | `pnpm turbo run {script} --filter={filter}` |

Only `lint` and `test` — never `build`. Empty matrix → skip sentinel.
