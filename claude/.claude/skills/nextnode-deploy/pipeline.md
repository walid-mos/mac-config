# Pipeline Architecture

## Flow

```
Caller repo                    NextNode core
────────────                   ─────────────
.github/workflows/ci.yml
  │
  └─► uses: pipeline.yml@main
        │
        ├── plan job
        │     uses: setup (infra mode)
        │     runs: tsx src/index.ts
        │     reads: nextnode.toml
        │     outputs: quality_matrix, project_name, project_type
        │
        ├── quality job (matrix)
        │     uses: setup (deps mode)
        │     runs: matrix.task.cmd (pnpm lint, pnpm test, etc.)
        │
        └── post-quality (one of)
              ├── publish      (type=package)
              ├── deploy-dev   (type=app, env=development)
              └── deploy-prod  (type=app, env=production)
```

## Reusable workflow: `pipeline.yml`

```yaml
on:
  workflow_call:
    inputs:
      config_file:    # default: "nextnode.toml"
      environment:    # default: "development"
```

Called by every NextNode project. No project defines its own CI jobs.

## Composite action: `setup/action.yml`

Two modes, controlled by inputs:

| Input   | Default   | What it does                                            |
| ------- | --------- | ------------------------------------------------------- |
| `infra` | `"false"` | Sparse-checkout core infra into `.infra/`, install deps |
| `deps`  | `"true"`  | Install caller project's own dependencies               |

Both always: checkout caller repo, setup pnpm, setup Node 24 with cache.

## Quality matrix

Generated by `buildQualityMatrix(scripts, project)`:

| Condition                 | Command format                                   |
| ------------------------- | ------------------------------------------------ |
| `project.filter` is false | `pnpm {script}`                                  |
| `project.filter` is set   | `pnpm turbo run {script} --filter={filter}`      |

Only `lint` and `test` are included. `build` is never in the quality matrix.

When no tasks are enabled, the skip sentinel fires:
```json
[{ "id": "skip", "name": "No quality checks", "cmd": "echo skipped" }]
```

The quality job checks `fromJSON(quality_matrix)[0].id != 'skip'` to decide whether to run.

## Plan outputs

Written to `GITHUB_OUTPUT` by `writePlanOutputs()`:

| Key              | Source                | Used by               |
| ---------------- | --------------------- | --------------------- |
| `quality_matrix` | `buildQualityMatrix`  | quality job matrix    |
| `project_name`   | `config.project.name` | post-quality jobs     |
| `project_type`   | `config.project.type` | post-quality routing  |

## Post-quality routing

Exactly one post-quality job runs per pipeline invocation:

| Condition                                | Job         |
| ---------------------------------------- | ----------- |
| `project_type == "package"`              | `publish`   |
| `project_type == "app"` + env=development | `deploy-dev` |
| `project_type == "app"` + env=production  | `deploy-prod` |

All three are currently stubs (echo-only). Implementation comes later.

## Monorepo pattern

For a turborepo monorepo, each package has:

1. Its own workflow file with `paths:` trigger filter
2. Its own `nextnode.toml` with `filter` set
3. Calls the same `pipeline.yml`

```
core/
├── .github/workflows/
│   ├── logger.yml          paths: ['packages/logger/**']
│   ├── standards.yml       paths: ['packages/standards/**']
│   └── infrastructure.yml  paths: ['packages/infrastructure/**']
├── packages/
│   ├── logger/nextnode.toml        filter = "@nextnode-solutions/logger"
│   ├── standards/nextnode.toml     filter = "@nextnode-solutions/standards"
│   └── infrastructure/nextnode.toml filter = "@nextnode-solutions/infrastructure"
```

A PR touching `packages/logger/src/format.ts` only triggers `logger.yml`. The quality matrix runs `pnpm turbo run lint --filter=@nextnode-solutions/logger` and `pnpm turbo run test --filter=@nextnode-solutions/logger`.
