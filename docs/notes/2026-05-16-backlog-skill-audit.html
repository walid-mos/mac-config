Why /backlog produced 37 tasks instead of 60

2026-05-16 · target: ~/.stow_repository/claude/.claude/skills/backlog/SKILL.md
"Audit why this happened, what we can improve in our plan so it solidifies our backlog, and to get a task list that would be perfectly ready and atomic enough for our agents to knock down without error?"

Observation. backlog-bundle.json bundle of 20 decisions (Agent Cockpit, greenfield V8) → 37 tasks. decision_refs coverage 20/20 ✓ but the backlog is not shippable: greenfield plumbing missing (prompt input, settings, code signing), multi-PR tasks merged at the surface (4 SQLite tables in one task, 4 trait methods in one task), no end-to-end demo path, V1 and V2 mixed together.

Single root cause. The skill treats every Decision as a monolithic coverage unit, never as a decomposition into mechanical atoms. The "≥1 task per D" check masks intra-Decision under-scoping. On greenfield, the Phase 3.5 enrichment pass is even disabled — so zero safety net.

Plan. 8 fixes (F1–F8) grouped into 3 patch levels. The Standard level (F1+F2+F3+F4+F6+F7) closes 95 % of the gap and takes the same bundle to ~55-60 shippable V1 tasks + ~15 parked V2 tasks.

R1
No decomposition at the Mechanism level
The mechanism cell of each Decision describes N concrete artifacts (a/b/c/d, files, functions, tables). The skill says nowhere: "each mechanical atom = ≥1 atomic task". Result: D1 (4 atoms) → 3 tasks; D10 (3 diff functions + React selector) → selector merged into another task.
High
F1 Phase 3.1 — parse atoms + target heuristic ceil(M×1.3)
R2
Cross-cutting plumbing missing (especially greenfield)
No Decision covers: prompt input for the agent, settings panel, macOS code signing, error boundary, empty/loading/error states, IPC type bindings, cancel/stop. Yet these tasks are mandatory to ship. The Phase 3.5 enrichment is disabled on greenfield — which is exactly the case where you'd need more of it, not less.
High
F2 Phase 3.2 — mandatory checklist per change_kind
R3
One-way coverage check
The "every D must have ≥1 task" rule passes green with a single task per Decision. Missing: reverse Mechanism check (every cited artifact must appear in a WHERE), Verification chain check (every ≥3-step sequence must have a demo-path task).
High
F3 reverse checks + Verification path mapping
R4
No target-count heuristic
Nothing in the skill says "a Decision with 4 Mechanism atoms should produce 5-7 tasks". The agent intuitively calibrates around ~1.8/D instead of ~3/D. No quantitative safety net.
Med
F1 + F6 histogram preview
R5
No anti-batching audit
The "no and/&/+ in the title" rule is too easy to bypass with a vague title: "SQLite schema initialization" = 4 tables, "AgentRuntime trait" = 4 methods, "GH Releases workflow" = CI matrix + tag + binary + notarization. Atomic on the surface, multi-PR in scope.
Med
F4 plural regex + LOC estimate + forbidden patterns
R6
V1 / V2 mixed without flag
The bundle explicitly marks D9/D12 = "V2", D16 = "V2 feature — not in V1", D18 = "First post-MVP feature". The skill stacks these tasks in the same backlog as V1 (Phases 6-7). The user has no idea what ships now vs later.
Med
F5 scope: "mvp" | "vnext" field + dual JSON
R7
No end-to-end "demo path" task
Each Decision has its own Verification. No task represents the full demo chain proving the MVP slice works (e.g. "open repo → run agent → see 3 diff views"). The user has to guess that it's T5.03 + T4.05 + T3.05 chained together.
Low
F3 + dedicated theme: "demo-path" task

8 proposed fixes

F1Phase 3.1 — Mechanism decompoHigh
Parse mechanism: extract atoms (a/b/c, enumerations, concrete artifacts, UI/IPC/backend layers). 1 atom = ≥1 candidate task. Merge ONLY if same file + <50 LOC each. Heuristic: tasks_for_decision ≥ ceil(M × 1.3).
Covers R1, R4Impact +12 tasks
F2Phase 3.2 — plumbing checklistHigh
Mandatory generation (greenfield): app identity, IPC bindings, settings panel, logging, error boundary, empty/loading/error states, cancel, user input surfaces, code signing. decision_refs: [] + theme: "plumbing" exempts these tasks from coverage.
Covers R2Impact +12 tasks
F3Reverse coverage + demo pathHigh
Three reverse checks before Phase 4: Mechanism artifact (every concrete token must appear in a WHERE/DONE WHEN) · Verification chain (each sequence → 1 task with theme: "demo-path") · tasks/Decision histogram with threshold.
Covers R3, R7Impact +3 tasks
F4Phase 3.3 — anti-batching auditMed
Regex on titles (concrete plurals, numbers). Description: WHERE >3 files → split. DONE WHEN >3 bullets → extract. Forbidden patterns: "Create all N tables", "Implement Trait with N methods", "Setup CI". Estimated LOC >300 → split.
Covers R5Impact +6 tasks (split)
F5Explicit V1 / V2 splitMed
Parse Decision.edge to detect "V2", "post-MVP", "future" → tag scope: "vnext". Emit two files: tasks-mvp.json and tasks-vnext.json. User confirms push independently.
Covers R6Impact V2 parked separately
F6Phase 4 — enriched diagnostic previewMed
Before go: tasks/Decision histogram, list of uncovered Mechanism artifacts, list of orphan Verification paths, plumbing checklist with ✓/✗. User can say split D1 and D10 or add the missing plumbing before push.
Covers R3, R4Impact user confidence
F7Explicit two-passMed
Pass 1 = explosion (default = too fine). Pass 2 = merge ONLY if same file + same conceptual surface + combined LOC <100 + same test. Invert the current bias (which starts high and never splits).
Covers R1, R5Impact structural
F8Effort estimate V12/V8/I6/I4/I3Low
Each task carries effort: "I3"|"I4"|"I6"|"V8"|"V12". Any V8/V12 blocks Phase 4 (must be split). Aligns the backlog with the global CLAUDE.md convention.
Covers R5Impact final safety net
